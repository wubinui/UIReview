UIReview Privacy Policy

Effective and last updated September 20, 2026

UIReview processes interface inspection and screenshot drafts locally. It sends feedback only after you press Send, directly to the Feishu/Lark destination you selected using your own self-built application. UIReview has no cloud backend, analytics, advertising, or sale of user data.

1. Scope

This policy explains how the UIReview Chrome extension handles user data. UIReview is an interface inspection and visual-feedback tool. It does not operate a UIReview cloud backend and does not use advertising or analytics SDKs.

2. Data UIReview handles

  • Website content and interface data. When you activate an inspection tool, UIReview reads the current page's DOM structure and visible element information, including text, computed CSS, layout, spacing, typography, colors, and iframe context. UIReview does not read cookies, passwords, form submissions, or network request bodies for this feature.
  • Screenshots and annotations. When you start Capture region, UIReview captures the visible tab, crops it to the region you choose, and may add your visual annotations.
  • Feedback and page context. UIReview handles your issue description, optional note, current page title, current page URL, viewport size, selected screenshot, and selected destination while you prepare feedback. The exact fields written to Feishu/Lark depend on whether the destination is a document or spreadsheet.
  • Feishu/Lark authentication information. If you connect a self-built application, UIReview handles the App ID and App Secret you provide. They are sent only to Feishu Open Platform to obtain a temporary tenant access token.
  • Destination information. UIReview handles document, spreadsheet, sheet, or Wiki identifiers and links, destination names, and your selected destination so it can validate and reuse them.
  • Clipboard data. UIReview writes a color value to the clipboard only when you choose Copy in the eyedropper. It does not read clipboard contents.

UIReview does not collect names, email addresses, payment data, health data, precise location, advertising identifiers, or browsing history unrelated to its interface-inspection and feedback features.

3. Collection and processing

  • Page interface data is read locally only while you use UIReview's inspection tools.
  • A visible-tab image is captured only after you start the screenshot feature and select a region.
  • Feedback is prepared locally and transmitted only after you choose a destination and press Send.
  • Feishu/Lark credentials are collected only when you enter them in UIReview settings and press Continue. UIReview uses them to authenticate with Feishu/Lark and stores them locally for later submissions you request.
  • A destination link is sent to Feishu/Lark for validation only when you add or select that destination.

UIReview uses this data solely to inspect the current interface, create the requested screenshot or annotation, validate your destination, and send your feedback. It is not used for advertising, profiling, credit decisions, generalized market research, or any unrelated purpose.

4. Local storage and retention

  • DOM, style, layout, and typography data is processed in browser memory and is not saved to chrome.storage.local.
  • Screenshot drafts, annotations, issue text, and notes remain in browser memory during the active workflow. They are cleared when the workflow is cancelled or completed, the page is reloaded or closed, or the extension process ends. UIReview keeps no separate local archive of submitted feedback.
  • Your Feishu/Lark App ID, App Secret, saved destination metadata, and selected destination remain in chrome.storage.local until you clear the connection in settings or uninstall UIReview.
  • A Feishu/Lark tenant access token is cached only in the extension service worker's memory until it expires, you clear the connection, or the service worker stops.

UIReview does not use Chrome Sync for these values. The UIReview developer does not receive or retain them on a UIReview server.

5. Sharing and external transmission

UIReview shares data only with the Feishu/Lark Open Platform, using your own self-built application, when required for a feature you explicitly request:

  • App ID and App Secret are sent to Feishu/Lark to authenticate your application.
  • Destination links or identifiers are sent to Feishu/Lark to resolve and validate the destination.
  • After you press Send, a Feishu document receives the issue description, screenshot, page title, page URL, viewport size, and submission time. A spreadsheet receives the page title, screenshot, issue description, optional note, and review status.

All external transmissions use HTTPS. Content written to Feishu/Lark is governed by your organization, application permissions, destination access, and Feishu/Lark's own terms and privacy practices. UIReview cannot access or delete that cloud content on your behalf.

UIReview does not send data to UIReview-controlled servers, analytics providers, advertisers, or data brokers. It does not sell user data or permit the developer or other humans to read it. It does not transfer data for personalized advertising, retargeting, or monetization.

6. Security

Stored configuration remains in your local Chrome extension storage. UIReview configures that storage for trusted extension contexts where Chrome supports the restriction; its code does not inject credentials into inspected pages or expose them to UIReview content scripts. Credentials and feedback are transmitted only to https://open.feishu.cn/ over HTTPS.

No storage or transmission method is completely secure. Protect your Chrome profile and use a dedicated Feishu/Lark application with only the required permissions. If credentials may have been exposed, rotate the App Secret in Feishu/Lark and clear the saved connection in UIReview.

7. Chrome permissions

  • activeTab — captures the visible tab only for a screenshot you initiate.
  • storage — stores connection details and reusable destination metadata locally.
  • clipboardWrite — copies a selected color; UIReview does not read the clipboard.
  • Website access (<all_urls>, including frames) — enables user-initiated inspection and region selection on arbitrary pages and visible iframes. It is not used for background tracking or advertising.
  • https://open.feishu.cn/* — authenticates your application, validates destinations, uploads screenshots, and writes feedback to your selected destination.

8. Your controls and deletion

You control when UIReview opens, which tool runs, what region is captured, what feedback is written, which destination receives it, and whether to press Send.

Choose Clear in UIReview settings to delete the stored App ID, App Secret, saved destinations, and selected destination. Uninstalling UIReview removes its local extension data under Chrome's normal extension-removal behavior. To delete feedback already submitted to Feishu/Lark, delete it from the destination or ask its administrator; UIReview has no cloud copy to delete.

9. Chrome Web Store Limited Use

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements. Data is used only to provide or improve UIReview's single-purpose, user-facing review features. UIReview does not use or transfer user data for personalized advertising, sell it, use it for unrelated purposes, or permit human access except when you explicitly request support and consent to sharing specific information, or when required for security or applicable law.

10. Website

The UIReview website is static. It does not include UIReview analytics, advertising trackers, or an account system and does not intentionally set tracking cookies. The hosting provider may process standard request information, such as IP address and request headers, to deliver and secure the site under its own privacy practices.

11. Policy changes

If UIReview's data practices change, this policy will be updated before those practices are released. Material changes will also be disclosed through the extension or Chrome Web Store listing when required.

12. Contact

For privacy questions or requests, open an issue in the UIReview GitHub repository. Do not include App Secrets, screenshots, private document links, or other sensitive data in a public issue.
